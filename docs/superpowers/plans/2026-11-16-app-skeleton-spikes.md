# App Skeleton & Platform Spikes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Flutter app in `app/` that builds on all six targets, plus automated spikes proving that crypto, the local database, WebSockets and AAC voice playback work on each one, run in CI on every platform.

**Architecture:** One Flutter project (`app/`) with a minimal Riverpod + go_router shell. Each risk is a small "spike" module under `lib/spikes/` with a pure function that returns a result, exercised by unit tests on the Dart VM, by `flutter test --platform chrome` for the web, and by one `integration_test` that runs on real Linux, Windows, macOS, iOS-simulator, Android-emulator and Chrome targets in GitHub Actions. The spike outcomes are recorded in `docs/spikes/2026-11-platform-spikes.md`, which decides the voice format for plan 8.

**Tech Stack:** Flutter 3.50 stable (Dart 3), `flutter_riverpod`, `go_router`, `cryptography` + `cryptography_flutter`, `drift` + `drift_flutter`, `web_socket_channel`, `record`, `just_audio` + `just_audio_media_kit` (+ `media_kit_libs_linux`, `media_kit_libs_windows_audio`), `integration_test`. GitHub Actions (repo is public, so macOS/Windows minutes are free).

**Spec:** `docs/superpowers/specs/2026-11-15-famchat-design.md` (roadmap: `docs/superpowers/plans/2026-11-15-famchat-roadmap.md`)

## Global Constraints

- App code lives in `app/`. App id `dev.famchat.app` on Android (`applicationId`), iOS and macOS (`PRODUCT_BUNDLE_IDENTIFIER`). Display name "FamChat".
- Targets: iOS, Android, macOS, Windows, Linux, web. Every spike runs on all six or records why it can't (e.g. no microphone on CI).
- Add packages with `flutter pub add` (latest versions; verify current setup docs via context7 before writing platform config). No pinning below what pub resolves.
- Device certificate message = UTF-8 `"famchat-device-cert-v1"` ‖ `encPub` (32 B) ‖ `signPub` (32 B), Ed25519-signed by the identity key; binary values base64url **without padding** (from plan 1 / `docs/protocol.md`).
- Sealed box (spec): ephemeral X25519 → HKDF-SHA256 → XChaCha20-Poly1305. Envelope AEAD: XChaCha20-Poly1305 with 24-byte nonce.
- Voice target (spec): AAC-LC in `.m4a`, ~48 kbps mono. Fallback: Opus in `.ogg`.
- WebSocket auth will use a one-time ticket in the URL query (spec), so the spike must not depend on custom headers (browsers can't set them).
- Local Linux machine: Flutter at `~/development/flutter/bin`, Chrome via `CHROME_EXECUTABLE=~/.local/bin/google-chrome-flatpak`. No local Android emulator or Mac: those targets are verified in CI only.
- Server tests keep vitest `maxWorkers: 2`.
- Firebase (`flutterfire configure`) is **not** in this plan; it moves to plan 9 (push) so spikes stay free of native Firebase setup.

## Review Focus

1. **Dart-made device cert rejected by the server** (byte order, padding, context string) → the server's `verifyDeviceCert` accepts a cert generated by the Dart code. (Task 2 fixture + server test `accepts Dart-generated cert`.)
2. **Pure-Dart crypto too slow on web/Windows/Linux** (no `cryptography_flutter` there) → 100 envelope encrypt+decrypt round-trips finish under 2 s on Chrome; measured time is printed and recorded. (Task 2 test `envelope throughput`.)
3. **Drift on the web loses data on reload or fails to load the wasm** → a row written, database closed and reopened, row still there, on Chrome. (Task 3 integration test.)
4. **AAC `.m4a` won't play on Linux/Windows** (just_audio has no desktop backend) → bundled fixture loads with a duration of ~2 s and plays to the end on every target. (Task 5 integration test.)
5. **WebSocket drops binary frames or large text on some platform** → a 64 KB text frame and a binary frame echo back unchanged. (Task 4 test.)

### Task 2: Crypto spike + server interop

**Files:** Create `app/lib/spikes/crypto_spike.dart`, `app/test/crypto_spike_test.dart`, `app/tool/gen_cert_fixture.dart`, `server/test/fixtures/dart-device-cert.json`. Modify `server/test/lib.test.ts`.

**Interfaces:**
- Produces (plan 3 will grow these into the real crypto core):
  - `Future<Uint8List> deviceCertMessage(List<int> encPub, List<int> signPub)` — context ‖ encPub ‖ signPub (86 bytes).
  - `Future<({String identityPub, String encPub, String signPub, String certSig})> makeDeviceCert({SimpleKeyPair identity, SimpleKeyPair enc, SimpleKeyPair sign})` — base64url no padding.
  - `Future<Uint8List> sealBox(List<int> recipientPub, List<int> plaintext)` / `Future<Uint8List> openBox(SimpleKeyPair recipient, List<int> sealed)`. Layout: `ephPub(32) ‖ nonce(24) ‖ ciphertext ‖ mac(16)`. HKDF-SHA256 over the X25519 shared secret, salt = `ephPub ‖ recipientPub`, info = UTF-8 `"famchat-sealed-box-v1"`, 32-byte output.
  - `Future<Map<String, Object>> encryptEnvelope({chatKey, epoch, chatId, messageId, senderDeviceId, SimpleKeyPair signKey, List<int> plaintext})` and `Future<Uint8List> decryptEnvelope(...)` — `{v:1, epoch, nonce, ct, sig}` per spec; aad = UTF-8 `chatId|messageId|senderDeviceId` (literal `|`), `sig = Ed25519(ct ‖ aad)`, `ct` includes the MAC.
  - `String b64url(List<int>)` / `Uint8List b64urlDecode(String)` (no padding).
- Note: these formats are a spike proposal; plan 3 finalises them with test vectors.

- [ ] **Step 1:** `flutter pub add cryptography cryptography_flutter`.
- [ ] **Step 2: Write the failing tests** `test/crypto_spike_test.dart`:
  - `cert message layout` — length 86, first 22 bytes == `utf8.encode('famchat-device-cert-v1')`.
  - `cert verifies` — `Ed25519().verify(message, signature)` is true; flipping one sig byte → false.
  - `b64url has no padding` — `b64url([1,2])` has no `=`; round-trips.
  - `sealed box round-trip` and `sealed box tamper` — open returns plaintext; flipping any byte of the sealed box throws.
  - `envelope round-trip`, `envelope wrong aad fails` (different messageId → throws), `envelope bad sig fails`.
  - `envelope throughput` — 100 encrypt+decrypt of 1 KB with one chat key; `expect(elapsed, lessThan(Duration(seconds: 2)))`; `print` the ms.
- [ ] **Step 3:** Run `flutter test test/crypto_spike_test.dart`. Expected: FAIL (undefined).
- [ ] **Step 4:** Implement `crypto_spike.dart` with `Ed25519()`, `X25519()`, `Hkdf(hmac: Hmac.sha256(), outputLength: 32)`, `Xchacha20.poly1305Aead()`. Call `FlutterCryptography.enable()` in `main()` (no-op where unsupported).
- [ ] **Step 5:** Run `flutter test test/crypto_spike_test.dart` then `flutter test --platform chrome test/crypto_spike_test.dart`. Expected: PASS on both; record the throughput ms from each run.
- [ ] **Step 6:** Write `tool/gen_cert_fixture.dart` (fixed 32-byte seeds `0x01…`, `0x02…`, `0x03…` for identity/enc/sign via `newKeyPairFromSeed`; X25519 enc key from seed `0x02…`) that writes `server/test/fixtures/dart-device-cert.json` = `{identityPub, encPub, signPub, certSig}`. Run `dart run tool/gen_cert_fixture.dart`.
- [ ] **Step 7: Write the failing server test** in `server/test/lib.test.ts` `describe("verifyDeviceCert")`: `accepts Dart-generated cert` (import the JSON, expect true) and `rejects Dart cert with swapped keys` (expect false).   (This test is written after its subject exists on both sides; its RED is the swapped-keys case and the fixture-regeneration check: temporarily changing the context string in the generator must make `accepts…` fail. Do that once and revert.)

### Task 4: WebSocket spike
