# Games in Direct Chats Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tic-tac-toe, checkers and chess between the two people in a direct chat, played through encrypted `game`/`move` messages, with a game card in the timeline, an active-game bar and a full board screen.

**Architecture:** Pure-Dart rules engines (`lib/games/`) behind one `Board` interface. Game state is a pure replay of a chat's `move` rows in `seq` order, derived from `messagesProvider`. Two new plaintext kinds ride the existing outbox and hub unchanged; `move` is hidden from the timeline but is normal (non-silent) chat activity.

**Tech Stack:** Flutter, Riverpod 3, drift, `chess` 0.8.1 (MIT, chess.js port), bundled Noto Sans Symbols 2 font.

**Spec:** `docs/superpowers/specs/2026-11-17-dm-games-design.md`

## Global Constraints

- Direct chats only (`chat.kind == 'direct'`) with exactly two members; never offered in groups or read-only (former-partner) chats.
- No server change. `game` and `move` are sent **non-silent** (they push and count as unread).
- Game state must be a pure function of the stored rows; both devices must agree. Illegal/stale/wrong-sender moves are ignored silently.
- One unfinished game per DM; a `game` sent while another is unfinished is inert ("Game not started").
- `chess` dependency pinned exactly: `chess: 0.8.1`.
- Wire names: `tictactoe`, `checkers`, `chess`. Titles: `Tic-tac-toe`, `Checkers`, `Chess`.
- Checkers squares 0–31 over dark squares, row by row from the first player's side (see Task 2).
- Tests: `cd app && flutter test <path>`; full suite `flutter test` (the repo's CI command). `dart format` with the repo's line length (`app/analysis_options.yaml`), `flutter analyze` clean.

## Review Focus

1. **The other person moves while I have a piece selected** → my selection clears, the board shows their move, and I can't send a move computed from the old position. (Task 7 test `selection resets when the position changes`.)
2. **Two of my devices move at once** → the first stored wins; the other device's board snaps back to the derived state with no error. (Task 5 test `second move with same ply is ignored`.)
3. **A `game` message shows up in a group** (old/hand-crafted client) → card renders as inert, moves are ignored, no bar. (Task 5 test `games in a chat without exactly two members are inert`.)
4. **Read-only DM (former partner) with an unfinished game** → the board opens view-only; no resign/draw/move controls; the Game menu entry is hidden. (Task 8 test `read-only chat shows board without controls`.)
5. **Long chess game** (200 plies) → opening the chat stays snappy. (Task 3 test `replays 200 plies quickly` with a generous 500 ms bound.)

### Task 2: Checkers engine (American rules)

**Files:**
- Create: `app/lib/games/checkers.dart`
- Modify: `app/lib/games/rules.dart` (`initialBoard`)
- Test: `app/test/games/checkers_test.dart`

**Interfaces:**
- Produces:
  ```dart
  enum CheckersPiece { man, king }
  class CheckersSquare { const CheckersSquare(this.side, this.piece); final Side side; final CheckersPiece piece; }
  class CheckersBoard implements Board {
    static int rowOf(int sq); static int colOf(int sq); // geometry below
    static int? squareAt(int row, int col);            // null on light squares/out of board
    CheckersSquare? at(int sq);
    List<List<int>> legalPaths();                       // every full legal move, as wire paths
    List<int>? get lastPath;
  }
  ```
- Geometry (wire format, also documented in Task 4): `row = sq ~/ 4` (row 0 = first player's back rank), `col = 2 * (sq % 4) + (row.isOdd ? 1 : 0)`. First player's men start on 0–11 and move toward higher rows; second's on 20–31 move toward lower rows.
- Move: `{"path": [from, landing1, landing2, ...]}`.
- Rules: men move one square diagonally forward; kings one square any diagonal; capture by jumping an adjacent opponent onto an empty square; **if any capture exists, a capture is mandatory**; a capture sequence must continue while further captures exist from the landing square; a man reaching the far row is crowned and the move ends there. Outcome: side to move with no legal path loses (`Outcome(other, 'no_moves')`). No automatic draws.

- [ ] **Step 1: Write failing tests**: `geometry: 0 is (0,0), 4 is (1,1), 31 is (7,7), light squares map to null`; `opening position has 7 legal paths for first`; `simple move [9,13] is legal; [9,14] (not adjacent) → null`; `capture is mandatory: a non-capturing path is rejected when a jump exists`; `double jump must be completed: a path stopping after the first jump is rejected`; `man crowned on far row and move ends even if a further jump exists`; `king moves backward`; `side with no pieces or no moves loses with no_moves`. Build mid-game positions with a test-only constructor `CheckersBoard.custom(Map<int, CheckersSquare> pieces, Side toMove)` (annotate `@visibleForTesting`).
- [ ] **Step 2: Run** `flutter test test/games/checkers_test.dart` → FAIL.
- [ ] **Step 3: Implement** `checkers.dart`; `legalPaths` via depth-first search of jump sequences from each piece, falling back to simple moves only when no jump exists anywhere. `play` = path ∈ `legalPaths()`.

### Task 5: Game state derivation

**Files:**
- Create: `app/lib/games/game_state.dart`, `app/lib/games/providers.dart`
- Test: `app/test/games/game_state_test.dart`

**Interfaces:**
- Consumes: Tasks 1–4.
- Produces:
  ```dart
  class GameState {
    final String id;                 // the game message id
    final GameType type;
    final String firstUserId, secondUserId;
    final Board board;
    final int ply;                   // next expected ply
    final Outcome? outcome;          // board outcome, or resigned/agreed
    final String? drawOfferedBy;     // userId with a pending offer
    final bool inert;                // never started (another game was running, or not a 2-person chat)
    final int? startedSeq;
    bool get over => outcome != null;
    String? get toMoveUserId;        // null when over or inert
    Side? sideOf(String userId);
    String? winnerUserId;            // null for draw / not over
  }
  /// [rows] as `watchMessages` orders them (seq ascending, pending last). [memberIds] the chat's members.
  List<GameState> deriveGames(List<MessageRow> rows, List<String> memberIds);
  GameState? activeGame(List<GameState> games); // the unfinished, non-inert one
  final gamesProvider = Provider.family<List<GameState>, String>(...); // from messagesProvider + membersProvider
  ```
- Algorithm: walk rows in the given order. A `game` row (failed state skipped) becomes a game whose second player is the other member; it's inert if `memberIds.length != 2`, `first` isn't a member, or another non-inert game is unfinished at that point. A `move` row applies to its target game only if: not `failed`; game exists, not inert, not over; sender is a player; `ply == game.ply`; then by `action.type`:
  - `play`: sender is `toMoveUserId` and `board.play(action minus 'type')` non-null → advance board, `ply++`, clear `drawOfferedBy`, outcome = board outcome.
  - `resign`: outcome = `Outcome(otherSide, 'resigned')`.
  - `draw_offer` (only if `board.drawOffers`): `drawOfferedBy = sender`.
  - `draw_accept`: only if `drawOfferedBy` is the other player → `Outcome(null, 'agreed')`. `draw_decline`: same condition → clear the offer.
  - anything else: ignored. Non-play actions don't change `ply`.
  Because games end at a point in this walk, "unfinished at that point" falls out of processing rows in order.

- [ ] **Step 1: Write failing tests** (build `MessageRow`s with a small helper): `a played game advances and alternates turns`; `move from the wrong player is ignored`; `second move with same ply is ignored` (two `play` rows by the same user at ply 0 → only the first applies); `illegal play is ignored and later legal one applies`; `resign ends with the other player winning`; `draw offer then accept is a draw; accept without offer ignored; decline clears; opponent play clears offer`; `tic-tac-toe ignores draw_offer`; `second game while one is unfinished is inert and its moves ignored`; `a game started after the first finished is active`; `games in a chat without exactly two members are inert`; `pending local move applies optimistically after sent moves`; `failed rows are ignored`.
