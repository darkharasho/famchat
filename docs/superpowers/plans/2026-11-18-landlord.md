# Landlord Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Landlord, a two-player, full-rules property-trading game, and let a DM run one long game (Landlord) alongside one quick game.

**Architecture:** `LandlordBoard` implements the existing `Board` interface. It is an immutable value holding the whole state, including the generator state, decks and phase. `toMove` is whoever must act now: a debtor, an auction bidder, a trade receiver, or else the turn player. Replay, pokes, labels, resign and rematch carry over. The long-game slot is a per-kind inert rule in `deriveGames`/`GameCache`, plus a kind argument on `activeGame`.

**Tech Stack:** Flutter/Dart, flutter_test (VM and `--platform chrome`), Riverpod. The seed and generator are in `app/lib/games/rng.dart` (merged in #68).

**Spec:** `docs/superpowers/specs/2026-11-18-go-fish-and-landlord-design.md`. Read its "One long game alongside one quick game" and "Landlord" sections. Everything about seeds, the generator and Go Fish is already merged.

## Global Constraints

- Wire name `landlord`, title `Landlord`. `drawOffers` is true. The first player in the `game` message goes first.
- Permanent wire format: the board table, the card lists in their pre-shuffle order, the dice draw, the shuffle order (Luck first, then Family Fund), and every action name and field. Changing any of these changes past games.
- `play` is pure. It never throws or mutates, and returns null for anything malformed or illegal. Read every wire number through `wireInt`.
- VM and web must agree. Use only `Rng` for luck, and no `1 << 32` or other bit tricks beyond what `Rng` does. Amounts are small ints.
- No trademarked names or text. Don't use "Monopoly", "Chance", "Community Chest", "Free Parking", "Boardwalk", "Park Place", "Water Works", "Electric Company" or any other space name from that game. Names are ours (below).
- Prices show as `$`. Hidden information: Landlord has none except the deck order. The UI never shows upcoming cards.
- App test runs never touch the real keyring or D-Bus. Run builds and test suites one at a time.

## Review Focus

1. **A non-turn player falls into debt mid-turn.** Family Fund "collect 10 from the other player", or the turn player owing rent with a debt then paid off, must resume the turn player exactly where they were. Tested in Task 5.
2. **The third failed jail roll without 50 in cash** puts the player in debt. Once it's paid, the move by that roll happens and its space resolves. Tested in Task 5.
3. **A card move lands on another card space.** Luck "go back 3" from #36 lands on #33, Family Fund, and draws from the other deck. Tested in Task 2.
4. **A debtor holding a hotel during a house shortage** can always sell it and raise its full value. Auto-bankruptcy counts that value. Tested in Task 3 and Task 5.
5. **A quick game started while Landlord runs,** then a second quick game, interleaved through `GameCache` re-derives: only the second quick game is inert, and the cache agrees with `deriveGames`. Tested in Task 6.

## Engine decisions (apply to Tasks 1–5)

These are the calls the spec leaves to the builder, fixed here so every task agrees.

- **Files.** The engine lives in `app/lib/games/landlord/`:
  - `spaces.dart`: the table and groups.
  - `cards.dart`: the cards.
  - `events.dart`: the log.
  - `landlord.dart`: `LandlordBoard`.
  Tests are in `app/test/games/landlord/`, with shared helpers in `helpers.dart`.
- **Dice.** A roll is `d1 = rng.randInt(6) + 1`, then `d2 = rng.randInt(6) + 1`. The utility card's "fresh roll" draws a new pair the same way.
- **Generator state.** `Rng(seed)` is created at setup, then Luck `[0..15]` is shuffled, then Family Fund `[16..31]`. The board stores `rng.state`. Each `play` resumes with `Rng(state)`, which is exact because the state is never 0.
- **Decks.** A deck is a `List<int>` of card ids, with the top at index 0. A drawn card is removed and put on the bottom **before** its effect applies. A get-out-of-jail-free card is not put back: the drawer holds it. Held cards are a `List<int>` of card ids per side, in the order received. Using one (`use_card`) takes the first held card and puts it at the bottom of its own deck. A trade of `cards: n` moves the giver's first `n` held cards to the end of the receiver's list.
- **Levels.** Each space has a building level 0–5, where 5 is a hotel. Bank stock is derived from the board, never stored: houses left = `32 − Σ levels in 1..4`, hotels left = `12 − count(level 5)`.
- **Internal stage** of the turn player: `roll`, `buy`, `end`, or `jailMove`. `jailMove` is never visible: it's the third failed jail roll waiting on its 50 debt. The board also keeps:
  - `again` (doubles: roll again after this),
  - `doubles` (doubles so far this turn),
  - `dice` (last roll, or null),
  - `auction`, `trade`, and `debts` (a queue).
- **Public phase** is `LandlordPhase { roll, buy, end, auction, trade, debt }`: `debt` if debts are non-empty, else `auction`, else `trade`, else the stage. `toMove` follows the same order: the first debt's debtor, the bidder to act, the trade receiver, or the turn player.
- **Settle.** After every successful action, `_settle` runs:
  1. While the first debt's debtor has the cash, pay it and pop it.
  2. If the first debtor's cash plus liquidation value is below what they owe, they go bankrupt: outcome (other side, `'bankrupt'`).
  3. When no debts are left and the stage is `jailMove`, do the stored move. That may create debts, so loop.

  Liquidation value is the sum of:
  - **Buildings:** for each building level (a hotel counts as 5), half that property's house cost.
  - **Mortgages:** half the price of each unmortgaged property the debtor owns.
- **Resolution order.** When resolving a landing:
  1. Set the next stage first: `buy` for an unowned property, otherwise `again ? roll : end`.
  2. Then charge any payment. A payment is always the last step, so a debt never interrupts the rest of a resolution. The exception is `jailMove`, above.
- **Auction.** State: space, high bid (0 means none), high bidder, bidder to act, and whether a no-bid pass has happened.
  - `bid` must be at least `high + 1` and at most the bidder's cash. The turn passes to the other bidder.
  - `pass` with a standing bid: the high bidder wins and pays. `pass` with no bid: the first such pass hands the turn to the other player; the second leaves the property with the bank.
  - Afterwards the stage becomes `again ? roll : end`.
- **Trade.** The offer is stored as `(giveCash, giveSpaces, giveCards, getCash, getSpaces, getCards)`. The fields are re-checked on accept, but nothing can change in between, because only the receiver can act.
  - On accept, things swap, then each receiver of a mortgaged property owes the bank interest of `ceil(mv/10)`, where `mv = price ~/ 2`. The turn player's interest is queued first.
  - Unmortgaging costs `mv + ceil(mv/10)`. In code: `(mv + 9) ~/ 10` for the ceiling.
- **Who may act:**
  - `sell` and `mortgage`: whoever is `toMove`, whenever no trade is pending.
  - `build`, `unmortgage` and `offer`: only the turn player, only with no debt, auction or trade, and only in stage `roll` or `end`.
  - `bankrupt`: only the debtor in `debt`.
- **Jail.** Space 10. Going to jail sets position 10, `inJail`, tries 0, `again = false`, `doubles = 0` and stage `end`. It never passes Start.
- **Start.** Collect 200 when a forward move passes or lands on 0. Moving back 3 never collects.
